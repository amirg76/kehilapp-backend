# הרצה מקומית — להפעיל את זה על המחשב

> **מה המדריך הזה עונה עליו:** צעד-אחר-צעד להרצת ה-Backend על המחשב שלכם,
> ומה כל צעד עושה. מיועד גם למי שלא הריץ שרת Node בעבר.

---

## מה צריך שיהיה מותקן

| כלי | למה | בדיקה שקיים |
|---|---|---|
| **Node.js** (גרסה 20+) | מריץ את הקוד | `node --version` |
| **MongoDB** | מסד הנתונים | `mongod --version` |
| חשבון **AWS S3** | לקבצים מצורפים | (אופציונלי לפיתוח בסיסי) |

> **טיפ:** אם אין לכם MongoDB מותקן, אפשר להריץ אותו בקלות דרך Docker:
> `docker run -d -p 27017:27017 mongo` — זה מדליק MongoDB בקונטיינר.

## הצעדים

### 1. התקנת החבילות

```bash
npm install
```

**מה זה עושה:** מוריד את כל הספריות שהקוד תלוי בהן (Express, Mongoose, bcrypt
ועוד) לתיקיית `node_modules`. פעם אחת מספיקה.

### 2. הגדרת משתני הסביבה

```bash
cp .env.example .env
```

ואז פותחים את `.env` וממלאים ערכים אמיתיים.

**מה זה "משתני סביבה" ולמה בקובץ נפרד?** אלה ההגדרות הרגישות — סיסמת המסד,
המפתח הסודי של הטוקנים, מפתחות AWS. הם **לא** בתוך הקוד, כי הקוד עולה לגיטהאב
ציבורי — והסודות אסור שיעלו לשם. הקובץ `.env` מוחרג מגיטהאב (ב-`.gitignore`),
אז הוא נשאר רק אצלכם.

**המינימום להרצה מקומית:**
```
NODE_ENV=local
MONGO_URI=mongodb://127.0.0.1:27017/kehilapp
JWT_SECRET=כל-מחרוזת-אקראית-ארוכה
```
(הקבצים ב-S3 יעבדו רק אחרי מילוי מפתחות AWS, אבל השאר ירוץ בלעדיהם.)

ליצירת מפתח סודי טוב:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### 3. זריעת נתוני דמו

```bash
node scripts/seedDemo.js
```

**מה זה עושה:** ממלא את המסד בתוכן דמה — 2 משתמשים (מנהל וחבר), 7 קטגוריות
והודעות. **כל התוכן מומצא**; אין בו שום נתון קהילתי אמיתי. הסקריפט מוחק תוכן
קודם לפני שהוא זורע, אז אפשר להריץ שוב בבטחה.

**אין סיסמה כתובה בקוד.** סיסמה שנכתבת בקובץ מתפרסמת יחד עם הריפו — וגם אם
מוחקים את השורה אחר כך, היא נשארת בהיסטוריה. לכן הסקריפט **מגריל סיסמה חזקה
לכל חשבון בכל הרצה ומדפיס אותה לטרמינל**:

```
done. sign in with:
  admin  admin@demo.example.com   <סיסמה שהוגרלה עכשיו>   (generated for this run)
  member member@demo.example.com  <סיסמה שהוגרלה עכשיו>   (generated for this run)
```

**מה זה נותן:** עדיין פקודה אחת בלי שום הכנה — רק שהסיסמה חיה בטרמינל שלכם
ולא בגיטהאב. הרצה חוזרת מגרילה סיסמאות חדשות, אז העתיקו אותן מיד.

רוצים סיסמה קבועה שלא משתנה בין הרצות? קבעו אותה בסביבה לפני ההרצה:

```bash
DEMO_PASSWORD='<בחרו סיסמה>' node scripts/seedDemo.js
```
או לכל תפקיד בנפרד — `DEMO_ADMIN_PASSWORD` ו-`DEMO_MEMBER_PASSWORD`.

### 4. הדלקת השרת

```bash
npm run local
```

**מה זה עושה:** מדליק את השרת במצב פיתוח. `nodemon` (הכלי מאחורי הפקודה)
מפעיל אותו מחדש אוטומטית בכל פעם ששומרים שינוי בקוד — נוח לפיתוח.

תראו בלוג:
```
server listening on port 5001 (local mode)
DB connected
```

השרת עכשיו חי על `http://localhost:5001`.

### 5. בדיקה שהוא עונה

```bash
curl http://localhost:5001/healthz
```
צריך להחזיר `{"status":"ok"}`. **זו בדיקת הבריאות** מ-[01 — ארכיטקטורה](01-architecture.md).

התחברות — **הסיסמה היא זו שהסקריפט הדפיס בשלב 3** (או זו שקבעתם ב-`DEMO_PASSWORD`):
```bash
curl -X POST http://localhost:5001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@demo.example.com","password":"<הסיסמה מהזריעה>"}'
```
צריך להחזיר טוקן.

אם איבדתם אותה — פשוט הריצו שוב את `node scripts/seedDemo.js`; הוא יגריל וידפיס
סיסמאות חדשות.

## הרצת הבדיקות

```bash
npm test              # הכל — 24 בדיקות
npm run test:unit     # רק המהירות (בלי מסד) — 8 שניות
npm run test:int      # רק אינטגרציה (עם מסד בזיכרון)
```

**חשוב:** הבדיקות **לא** נוגעות במסד שלכם. הן מדליקות מסד זמני משלהן בזיכרון
(ראו [03 — בדיקות](03-testing.md)). אפשר להריץ בבטחה בכל רגע.

## בדיקת איכות הקוד

```bash
npm run lint          # בודק סגנון ובעיות
npm run lint:fix      # מתקן אוטומטית מה שאפשר
```

זה בדיוק מה שרץ אוטומטית ב-CI על כל שינוי.

## תקלות נפוצות

| תסמין | הסיבה | הפתרון |
|---|---|---|
| `MONGO_URI is not defined` | חסר `.env` או ערך בו | ודאו ש-`.env` קיים ומלא |
| `ECONNREFUSED 27017` | MongoDB לא רץ | הדליקו MongoDB (או ה-Docker למעלה) |
| התחברות מחזירה 400 | אימייל לא בפורמט תקין | בדקו את גוף הבקשה |
| התחברות מחזירה 401 | סיסמה שגויה, או לא הרצתם seed | הריצו `node scripts/seedDemo.js` |
| הכל 429 | חרגתם ממגבלת הקצב | המתינו 15 דקות, או הריצו מחדש |

## מה הלאה — לקראת שרת אמיתי

ההרצה המקומית היא הצעד הראשון. השלבים הבאים (מחוץ למדריך הזה):

1. **Docker** — לארוז את השרת לקונטיינר, כדי שירוץ זהה בכל מקום
2. **Terraform** — להגדיר את שרת ה-AWS כקוד, כך שהתיעוד *הוא* התשתית
3. **פריסה** — להעלות לאוויר עם כתובת אמיתית, נתוני דמו בלבד

כל אלה נשענים על מה שכבר קיים: בדיקות הבריאות שה-Docker יבדוק, הכיבוי המסודר
ש-Docker מפעיל, והלוגים שיוצאים ל-stdout כמו שסביבת ייצור מצפה.
